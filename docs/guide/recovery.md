# Offline recovery and conflicts

**Status: accepted replacement-runtime obligations; qualification is pending.**
Preserve the state and exact evidence before taking corrective action. Missing,
invalid, unsatisfied, satisfied and disputed evidence are different conditions.

## Offline and uncertain outcomes

Independent authorized work can continue offline if the required membership,
rule and artifact proofs are held. New administrative changes wait for the
administrator; a unique choice waits for its named authority. Missing proof is
not permission and cannot become a negative review merely because a peer is slow.

After a lost reply, inspect or retry using the same logical request/effect
identity. A timeout does not prove a transaction failed. Reopen/replay must settle
an uncertain durable commit before further signing. Delivery retries expose one
logical inbox item and action. A handoff offer does not wake a remote machine.

## Conflicting authority and author history

Two incompatible successors of one scoped decision predecessor halt that scope.
Retain both records. Do not choose by arrival, timestamp or hash. Unrelated
streams and authorized work remain available.

A global author-log fork can affect later evidence from that author across
several scopes. Exact retained scoped proofs have limited admissibility rules;
they cannot bypass membership, a removal cutoff, wrong epoch, wrong subject or
the scope's own authority fork. An administrator-chain fork preserves its verified
prefix and blocks new governance depending on the disputed branch.

A new explicitly authorized round can continue after a scoped halt while naming
the prior round and fresh bindings. It does not declare a winner in the old fork
or rewrite signatures. Re-admission similarly cannot repair excluded old-tenure
history.

## Draft edits and local conflicts

Concurrent draft edits target an expected revision. One wins; the other retains
its work with a conflict, then reconciles deliberately. Validation belongs to
exact bytes/revision, and publish must not race a later edit. Existing task rules
stay pinned when future defaults change unless an explicit authorized revise or
reopen transition names the new context.

A stale code base, dirty target checkout or missing artifact blocks local apply.
Inspect and preserve local work before retrying. Never reset a person's checkout
or erase state because a diagnostic is inconvenient.

## Cancellation and redacted diagnosis

Cancellation requested is not stopped. Report an observed current execution
outcome: stopped, completed or uncertain. A remote message, stale PID or local
client exit is not authority to signal arbitrary processes or proof descendants
terminated.

Collect format/source identity, scope/round, exact subject IDs, missing proof
categories and redacted error text. Exclude credentials, tickets, private prompts,
provider environment values and raw transcripts. Keep retained evidence needed
to reproduce a verdict. No backup format is promised by this foundation: preserve
state and use only an actually supported backup/restore procedure when available;
do not copy a live database and describe it as qualified recovery.

## Backup and restore boundaries

A backup must identify exact current-format state, retained objects/proofs and
credential handling under an actually implemented procedure. Preserve the source
and format identity. A copied live database without a consistent retained-object
snapshot is not a qualified backup. Test restoration and same-model replay in a
separate selected location before relying on it; this foundation does not supply
a tested backup/restore command or data-conversion route.
