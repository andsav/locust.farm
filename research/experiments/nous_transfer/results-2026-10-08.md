# Nous transfer: interrupted Luna smoke run

Status: **partial live run; diagnostic only**. The smoke run completed 638 of
900 planned calls before three overlapping requests failed with `URLError`.
Further dispatch stopped after the first observed error. No failed requests were
retried and the replay cohort was not run. These data do not establish a Nous
forecasting benefit or a communication benefit.

The [protocol](README.md) describes the frozen design. The
[saved evidence](smoke-evidence-2026-10-08.json) contains original response text,
usage, timestamps, request hashes, minimal scoring labels, source/code hashes,
and recomputable summaries. It omits upstream prompt and research-brief bodies.

## Manipulation diagnostics

Equal UTF-8 byte padding did not achieve the stated token-balance target. Six
questions have all 30 initial calls available for a matched comparison. Published
profiles use 238.5 more input tokens on average than neutral profiles for each of
those questions; structured profiles use 135.9 more. The maximum/minimum ratio
differs by **9.37–11.29%**, exceeding the 5% target in all six matched questions.
Pooled input-token means also differ, but mix unequal case coverage and should
not substitute for those matched comparisons. No fully length-controlled claim
is supported.

## Integrity repair and verification

After network failures stopped dispatch, final verification exposed a separate
hashing bug. The reused transport hashes canonical JSON with compact separators;
the initial experiment verifier expected JSON with spaces. Every live request
therefore failed that comparison, despite the same reconstructed request body.
Offline simulated calls used the other hash format and did not catch this bug.

The corrected verifier uses the transport's hash function for live records and
the existing simulated format for dry runs. A regression test passes a mocked
HTTP response through the actual transport, checks saved/resumed verification,
and rejects a tampered request hash. Generation prompts, records, and the frozen
manifest were not changed. The original four code hashes are checked against
Git revision `83672e2`; all other manifest fields are rebuilt from pinned upstream
inputs before comparing the manifest hash.

Verification completed:

- All **641** attempted request hashes rebuilt and matched, including failed calls.
- Saved scores, diagnostics, usage accounting and reservation bounds recomputed.
- **18 Python tests passed**, including simulated branching, missing-input gates,
  live-transport hashing, tamper rejection and revision scoring.
- Documentation/index/link checks passed. No Rust code changed; no Rust build was
  required.

Reproduce the saved-evidence check from the repository root:

python3 research/experiments/nous_transfer/evidence.py verify research/experiments/nous_transfer/smoke-evidence-2026-10-08.json --upstream output/nous-paper-review-2026-10-07

The upstream checkout must be at the pinned commit. This verification makes no
model API calls. It verifies reconstruction against locally recorded hashes, not
a provider-signed attestation of requests or responses.

## Remaining work

The historical replay remains unrun. A new smoke protocol should first correct
token balance on development inputs, add frozen behavioral-direction probes, and
use a separately recorded attempt policy if transport retries are desired. It
must preserve this interrupted run rather than overwrite or silently fill its
missing observations. A scientific evaluation still needs a sufficiently large,
independent prospective cohort; this historical smoke cannot supply that evidence.
