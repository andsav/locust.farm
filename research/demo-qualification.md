only the local registry index and dependency archives; the locked build ran
offline without reusing a compiled target. Independent archive, manifest,
payload-size/mode/hash and embedded-version checks passed.

- Manifest SHA-256: `08353666e2befc985fad4f6be0090bc25f680c4ad635b2f7b6fffd049082141c`.
- Archive SHA-256: `5e8f5cb89f125c9ae042d89c5b7891927f31311d399ca340c7ef36e83f026685`.

The locally built binary was the trusted bootstrap. Disposable test signatures
qualified installation mechanics. The
[native campaign](../scripts/check_installed_clients.py) used actual native
clients, fresh private profiles, guarded loopback providers, dummy authentication
and synthetic repositories. Each client used the identity/session, MCP entry,
skill and launcher generated by `up`, with no initial work grants. Fixture owner
authorization was explicit and subsequent to onboarding.

## Corrections and retained failures

- The first workspace run exposed a test race: task replication preceded its
  later work offer. The test now observes exact offer readiness before starting
  once; the full workspace rerun passed.
- A recipe run passed its four cases but correctly rejected a debug binary
  replaced by a concurrent build. Stable-debug and packaged reruns passed.
- Initial service/native campaigns stopped on a removed grant flag in their
  harnesses. They now use the current `--grants` JSON contract.
- The second native campaign passed the workspace flow but rejected legitimate
  post-native profile bookkeeping changes. The corrected check still requires
  exact identity/launcher preservation and the following no-op retry.
- Review caught unsupported `task open --title` and obsolete workflow table
  commands. The corrected multiline task text and named administration sequence
  ran successfully. These documentation corrections and harness-only fixes
  follow the candidate commit; the production binary was not changed.

The [retained evidence](evidence/demo-qualification-2026-10-04.json) includes
artifact and harness identities, final assertions, earlier failed verdicts,
public identifiers, exact administration arguments, operation hashes and cleanup.
It excludes credential bytes, provider payloads and installed skill bodies.

## Limits

Scripted provider selection does not prove a real model choosing the skill or
following the new demo naturally. Interactive human approval, Pi, Linux/systemd,
production publisher trust and a complete two-physical-host demo were not tested.
The native work fixture uses one principal for worker/coordinator roles; the
two-member administration sequence is separate. Existing real-model collaboration
results retain their own candidate and method in the
[collaboration findings](collaboration-followups.md). Profile doctor intentionally
keeps native discovery unverified and `model_ready` false.
