# Host safety and ending a goal: what each part owns, removes and checks

Status: companion to the proposed
[host safety and ending plan](host-safety-and-ending-plan.md) of 2026-10-06.
Not accepted and nothing here is built.

For each of the three parts this lists what it owns, what it removes or
rewrites, the behaviors it must show with the test or command that shows
each, and what its writers could not settle. Where a list and the plan
disagree, the plan is right. A test named here that does not exist yet is one
the phase adds.

## The signing key (K1)

Owns:

- The term governance key and its code name `governance`; the rule that no text a person reads names it and that a record it signed prints as `host`
- What host names: the person whose computer holds the governance key (`Node::hosts(entry)`); what host's agent names: the agent the first record names; the rule that a key-typed field called `host` always means the host's agent; the fact that the endpoint in the host's agent's admission is the host's computer
- The first record: `Genesis { governance, host, definition, salt }`, `Genesis::goal_id` over all four fields, and the `Header::check` rules (author equals `governance`; `host` differs from `governance`)
- `Body::host_may_sign()`: the one list of kinds the governance key signs (governance kinds and `EffectMaterialized`; Phase 8 adds `ScopeDecided`); the term host step
- The table of which key signs each governance kind, each host step, each automatic record and an invitation, including that the first files are signed with the host's agent's key
- `History.host` and `State.host`
- Replay rules in `Chain::build`: an admission of the governance key is excluded; a removal of the host's agent is excluded
- The replay rule in `authorize_base`: a non-governance record by the governance key is `NotAMember` unless `host_may_sign()`, and then needs no tenure
- How a fork is judged per key: the governance log as the administrator's log today (`Halt::Fork`, permanent); the host's agent's log as any member's
- The local record `K` in `Space::Goal` (the governance seed per goal), `local::governance_write`, `Local.governance`; the fact of what a copy of the data directory holds and that a copy older than a goal holds neither the goal nor its key (the Backups section and the status line are G2's)
- `Node::key_for(entry, author)`; the governance-key branch of `Node::next_place`; the bodies of `Node::hosts` and `Node::host` after Phase 1; the fact that every signature with the governance key passes `next_place` except the three records of `goal_create`; `Node::author_alone`, the one way a record is signed with nobody present, and the admission signed with no clock reading
- The order in `plan_join`: a repeated join by a member already admitted is answered before K1's three tests and before any signature
- API fields: `GoalStatus.governance`, `GoalStatus.hosted_here`, `GoalStatus.host: Option<PublicKey>`, `ContextBrief.host: Option<PublicKey>`, `EventView.by_host`, `TaskView.by_host`
- What an invitation and a ticket commit to: the goal identifier and the governance key, signed by that key; what the public page's address commits to: its own upload key, tied to the goal by the publication policy the governance key signs
- The farm rules for the governance key: it is never a required author, so no consent is asked of it and none it signed is read; its records stay in the page's list of changes with no agent
- The answer on the host's agent: it can be disconnected (revoked) with every host command still working; it cannot leave or be removed; it keeps Phase 4's role fallback; a stage task's creator is the governance key; what waits while it is disconnected (its work, the roles only it holds, the first files, its page consent)
- The refusal of `workspace init` on the host's computer while the host's agent is disconnected (the matching line in the `agent revoke` plan is E2's)
- No request, no command, no new record kind and no new shared state are defined by this piece
